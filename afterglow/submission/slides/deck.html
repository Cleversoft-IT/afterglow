04 · why it's agentic

The model chooses tools, corrects itself, and exits explicitly.

1 · Self-correction on tool errors

Turn N: booking.create → validation_failed party_size required.
Turn N+1: re-read transcript, re-emit with party_size=4 → executed. Hard cap: 2 attempts per action.

2 · RAG-on-demand, not RAG-as-prefix

The agent decides whether to spend tokens on the Vector Store — and asks specific questions ("allergies on file?"), not catch-all queries. First-time caller: skip entirely.

3 · Explicit loop exit conditions

finalize → completed. max_turns → needs_review (first-class terminal, surfaced in the UI). error → failed. No silent fallback.

4 · Auditable turn-by-turn

Each turn → one audit row. Action results joined on payload.agent_turn (integer, not timestamps). The Agent Reasoning Trail is a first-class UI surface, not a buried log.

  • Speechmatics Batch STT on every call
  • Gemini 3.1 Flash Lite + ADK loop on every analyzed call
  • Vultr Serverless Inference RAG (non-zero input_tokens)
  • Vultr Vector Store preseeded at boot
  • Vultr Managed Postgres — system of record
  • customer.update_profile mutates the row (undoable)
  • Speechmatics TTS Preview generates every demo MP3

MOCKED · honest demo concession

  • booking.create — no Resy/TheFork account for N judges
  • whatsapp.* — per-message billing on a public demo
  • email.*, sms.* — verified-domain required
  • calendar.* — per-tenant OAuth
  • payment.* — never test against a live processor
  • crm.*, review.* — customer-specific choice
  • Vector Store write-back in demo (would pollute shared coll.)
Swap a mock for real = one file in action_catalog.py + env var. Not an architecture migration.
